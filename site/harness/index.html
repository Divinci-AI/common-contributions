The harness in detail · Common Contributions

How a contribution stays small, capped and reviewed.

This page is the detail behind the mission: every guard, what the dry run showed, and the honest state of each piece. Nothing here is installable yet.

Consent comes first

No file, no contact.

The proposed design has a project opt in with a single file. If it is absent, the tool does nothing there. You revoke it by setting one line to false. This is a design. Today the tool opts in by issue label and per-issue scope.

.github/AGENT-CONTRIBUTIONS.md   # name provisional

agent_contributions: true          # set false to revoke instantly
contact: maintainer@example.org    # a human who agreed to this
label: agent-ready
allowed_paths: ["src/**", "tests/**", "docs/**"]
forbidden_paths: [".github/**", "**/*.lock"]
requires_acceptance_test: true
max_diff_lines: 200
disclosure_line: "AI-assisted; reviewed by a human before submission"

A project never has to pay anything, accept any change, reply by a deadline, or run our software.

How a task runs

One issue. One file. Six steps.

  1. A maintainer opts one issue in. They label it agent-ready and write its scope: one file and a check for when it is done.
  2. The coverage gate looks first. If a test already covers the code and the issue does not say so, the run is refused.
  3. Spend is reserved before the call. The worst case is checked against your daily and total caps.
  4. The agent returns text. It has no shell and no tools. If it reports using any, the run stops.
  5. The harness writes the file and checks it. Secrets and stray URLs are scanned, then the project's own type check and tests run.
  6. Another model tries to break the tests. A person reviews the result. Nothing is published without that.

Spend cap$3 per day Armed

Stops a runaway loop, or a provider with no hard limit.

How

The worst case is reserved against the daily and total caps before every call. A model with no known price is refused.

Coverage gateevery test Armed

Stops writing a test that already exists.

How

Every test file is searched for imports of the module. The issue has to name each one it finds.

One file1 path Armed

Stops edits outside the task.

How

The result must be exactly the path in the issue. The harness writes the file itself, not the model.

Secret scanreply + file Armed

Stops keys and tokens leaking into output.

How

The reply and the written file are scanned for known secret shapes. The sandbox environment is an allowlist.

Egress allowlistmodel + git Armed

Stops the agent reaching anywhere else.

How

The harness's own requests may go only to the model endpoint and git. This checks what the harness sends; it is not an operating-system firewall, and running model-written code in a container is not built yet. Documentation hosts such as example.com count as fixtures, not calls.

Branch ruleagent/* only Armed

Stops anything landing on main.

How

The publish gate rejects any other branch name, including look-alikes and anything containing "..".

Main kill switch

One file, checked before every call. Three failures in a row trip it. Only a person clears it.

What this does not show yet

  • Two small modules, one model family writing tests, one author per mutation set.
  • In the dry run, the budget cap and measured token counts were never exercised (a later real run of the hosted adapter is in the status table above). The agents ran in a coding assistant that is not billed per token.
  • The count of tools an agent used is passed in by whoever runs the harness. The harness cannot verify it.
  • The container is tested on one runtime (macOS with OrbStack). A container escape would reach this Mac's home folder with your rights, and --allow-host-execution skips the container. The run record is made by the tool on your machine, so it is self-reported; a project's own CI is the real check.
  • No pull request has been opened from any of this, and no maintainer has reviewed the test files.

When there is something to install, the plan is one instruction to your agent. It would ask for three things: an API key with a spend limit you set, a list of projects you choose, and a daily budget. Until then, nothing on this page should be copied into a terminal.

Besides the guards

The rest of what it does.

Checks the work

  • Runs the project's own tests, not its own idea of them.
  • Scores the tests with mutations written by a different model than the one that wrote them.
  • Reports what it cannot know, such as the number of tools an agent used.

Keeps people in charge

  • A person clears the kill switch. The tool never does.
  • A person reviews and merges. The agent never does.
  • No rewards. Nothing is paid or credited for contributing.
