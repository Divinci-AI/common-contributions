Spare tokens. Open source. Every circuit has a breaker.

Common Contributions is a harness for your own AI agent. It takes on tiny, pre-approved tasks in projects that asked for help. You set the budget and hold the kill switch. A person reviews anything that leaves your machine.

How a task runs

One issue. One file. Six steps.

  1. A maintainer opts one issue in. They label it agent-ready and write its scope: one file and a check for when it is done.
  2. The coverage gate looks first. If a test already covers the code and the issue does not say so, the run is refused.
  3. Spend is reserved before the call. The worst case is checked against your daily and total caps.
  4. The agent returns text. It has no shell and no tools. If it reports using any, the run stops.
  5. The harness writes the file and checks it. Secrets and stray URLs are scanned, then the project's own type check and tests run.
  6. Another model tries to break the tests. A person reviews the result. Nothing is published without that.
Besides the breakers

The rest of what it does.

Checks the work

  • Runs the project's own tests, not its own idea of them.
  • Scores the tests with mutations written by a different model than the one that wrote them.
  • Reports what it cannot know, such as the number of tools an agent used.

Keeps people in charge

  • A person clears the kill switch. The tool never does.
  • A person reviews and merges. The agent never does.
  • No rewards. Nothing is paid or credited for contributing.

What this does not show yet

  • Two small modules, one model family writing tests, one author per mutation set.
  • The budget cap and measured token counts were never exercised. The agents ran in a coding assistant that is not billed per token.
  • The count of tools an agent used is passed in by whoever runs the harness. The harness cannot verify it.
  • There is no operating-system sandbox. The design depends on the agent returning text.
  • No pull request has been opened from any of this, and no maintainer has reviewed the test files.

For maintainers

No file, no contact.

The proposed design has a project opt in with a single file. If it is absent, the tool does nothing there. You revoke it by setting one line to false. This is a design. Today the tool opts in by issue label and per-issue scope.

.github/AGENT-CONTRIBUTIONS.md   # name provisional

agent_contributions: true          # set false to revoke instantly
contact: maintainer@example.org    # a human who agreed to this
label: agent-ready
allowed_paths: ["src/**", "tests/**", "docs/**"]
forbidden_paths: [".github/**", "**/*.lock"]
requires_acceptance_test: true
max_diff_lines: 200
disclosure_line: "AI-assisted; reviewed by a human before submission"

A project never has to pay anything, accept any change, reply by a deadline, or run our software.
